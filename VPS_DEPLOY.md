# Malik Team Connect — VPS Deployment Guide

Simple steps. Follow in order. Time: about 20–30 minutes.
You need: one VPS (Ubuntu 22.04 or 24.04, minimum 2 GB RAM) and one domain name.

What will run on the VPS (all inside Docker):

| Service | Work |
|---|---|
| backend | API, login, chat, call signalling |
| postgres | Database |
| livekit | Group calls |
| coturn | TURN server — calls work on different Wi-Fi / mobile data |
| caddy | HTTPS (automatic certificates) + reverse proxy |

---

## Step 1 — Buy the VPS and point your domain

1. Buy a VPS (Ubuntu 24.04, 2 GB RAM or more). Note its **public IP address**.
2. Open your domain's DNS settings.
3. Add these **A records** — all three point to the VPS IP:

   | Name | Type | Value |
   |---|---|---|
   | `api` | A | `<VPS IP>` |
   | `livekit` | A | `<VPS IP>` |
   | `turn` | A | `<VPS IP>` |

   Example: your domain is `myteam.pk`, then the apps will use
   `api.myteam.pk`, `livekit.myteam.pk`, `turn.myteam.pk`.
4. Wait 5–10 minutes for DNS. Check: `ping api.myteam.pk` — it should show your VPS IP.

## Step 2 — Upload the project to the VPS

1. On your computer, zip the `malik-team-connect` folder.
2. Upload it to the VPS (use your hosting panel, or `scp`):

   ```bash
   scp malik-team-connect.zip root@<VPS IP>:/root/
   ```

3. SSH into the VPS and unzip:

   ```bash
   ssh root@<VPS IP>
   apt-get install -y unzip
   unzip malik-team-connect.zip
   cd malik-team-connect
   ```

## Step 3 — Run the one-time setup script

```bash
chmod +x deploy/vps-setup.sh deploy/backup.sh
sudo ./deploy/vps-setup.sh
```

This script will:

1. Install Docker.
2. Open firewall ports: 22, 80, 443, 3478 (UDP+TCP), 5349, 7881, 7882/UDP,
   LiveKit media 50000–60000/UDP, coturn relay 60001–65000/UDP.
3. Create the `.env` file and **auto-generate strong secrets** (JWT, database, LiveKit, TURN).

## Step 4 — Edit `.env` (very important)

Open `.env` in the project root: `nano .env`

Set these lines with **your real domain**:

```ini
DOMAIN=myteam.pk
TURN_DOMAIN=turn.myteam.pk
TURN_REALM=turn.myteam.pk
CORS_ORIGINS=https://api.myteam.pk
LIVEKIT_URL=wss://livekit.myteam.pk
STUN_URLS=stun:turn.myteam.pk:3478,stun:stun.l.google.com:19302
TURN_URLS=turn:turn.myteam.pk:3478?transport=udp,turn:turn.myteam.pk:3478?transport=tcp
DATABASE_URL=postgres://postgres:postgres@localhost:5432/malik_team_connect
```

Notes:

- Do **not** change `DATABASE_URL` for Docker use — Docker Compose overrides it
  automatically with the correct container address and your `POSTGRES_PASSWORD`.
- Secrets were already generated by the setup script. To make a new one any time:
  `openssl rand -hex 32`
- `FIREBASE_SERVICE_ACCOUNT_PATH` — leave empty for now if you have no Firebase
  file. The app still works; only background push wake-up for calls is off.

## Step 5 — Set the 10 user passwords

1. Open `backend/seed/users.json`: `nano backend/seed/users.json`
2. There are 10 users: `malik1` … `malik10`. Change every password — the file has
   `CHANGE_ME_...` sample passwords. Use strong, different passwords.
3. Save the file. Never share this file with anyone, never put it on GitHub.
4. Give each team member only **their own** username + password.

## Step 6 — Start everything

```bash
docker compose up -d --build
docker compose ps        # all services should be: running / healthy
```

First start takes a few minutes (downloads + build). Caddy will get HTTPS
certificates automatically — this needs the DNS from Step 1 to be ready.

## Step 7 — Create the 10 accounts

```bash
docker compose exec backend npm run seed:prod
docker compose exec backend npm run seed:prod -- --check
```

The second command should print: `Users in database: 10 / max 10`.
The seed only prints usernames — never passwords or hashes.

## Step 8 — Test the API

```bash
curl https://api.myteam.pk/health
# answer: {"ok":true,"service":"malik-team-connect-backend"}

curl -X POST https://api.myteam.pk/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"malik1","password":"YOUR_PASSWORD_FROM_STEP_5"}'
# answer: a token + your user info. If this works, login works.
```

## Step 9 — Point the Android app at your VPS

In the Android project, set the server address to `https://api.myteam.pk`
(see the Android `ApiConfig` / `local.properties` example in the app folder).
Group calls use `wss://livekit.myteam.pk` — the app gets this from the backend,
no change needed in the app. Then build the release APK in Android Studio and
install it on the 10 phones.

## Step 10 — Test calls properly

1. Phone A on home Wi-Fi, Phone B on **mobile data** (Wi-Fi off).
2. Login with two different users, make an audio call, then a video call.
3. Start a group call with 3 phones.
4. If calls connect with audio/video both ways — deployment is complete. ✅

## Daily operations

| Task | Command (from the project folder) |
|---|---|
| See logs | `docker compose logs -f backend` (or `livekit`, `coturn`, `caddy`) |
| Restart one service | `docker compose restart backend` |
| Update after new code | `docker compose up -d --build` |
| Stop everything | `docker compose down` (data is safe — it is in Docker volumes) |
| Backup now | `./deploy/backup.sh` |
| Automatic daily backup | `crontab -e` → add: `30 3 * * * cd /root/malik-team-connect && ./deploy/backup.sh >> backups/backup.log 2>&1` |

**Backup rule:** copy the `backups/` folder to your own computer regularly.
A backup that stays only on the same VPS is not a real backup.

Restore a database backup:

```bash
gunzip -c backups/mtc-backup-<date>/db.sql.gz | docker compose exec -T postgres psql -U malik -d malik_team_connect
```

## Disable / remove a team member

There is no admin website (by design). Use SQL:

```bash
docker compose exec postgres psql -U malik -d malik_team_connect \
  -c "UPDATE users SET is_active=false, token_version=token_version+1 WHERE username='malik7';"
```

This blocks login **and** kills that user's existing sessions immediately.

## Optional: TURNS (TURN over TLS, port 5349)

By default, TURN runs on 3478 (UDP+TCP) — enough for normal use.
For extra-strict networks, add TLS:

1. Get a certificate for `turn.<DOMAIN>` (for example copy the cert Caddy
   stored in its `caddy_data` volume, or use certbot standalone while Caddy is stopped).
2. Mount the cert files into the coturn service and add `--cert` / `--pkey`
   flags — full notes are in `deploy/turnserver.conf.example`.
3. Add `turns:turn.<DOMAIN>:5349?transport=tcp` to `TURN_URLS` in `.env`,
   then `docker compose up -d`.

## Troubleshooting

| Problem | Check |
|---|---|
| `https://api.../health` does not open | DNS ready? `docker compose logs caddy` — certificate errors mean DNS is wrong or port 80 is blocked. |
| Login works, calls do not connect | Open `docker compose logs coturn livekit`. Check firewall ports (Step 3 list) also in your **hosting panel firewall**, not only ufw. |
| Group call fails, 1-to-1 works | `docker compose logs livekit`. Check `LIVEKIT_API_KEY/SECRET` in `.env` match (Compose passes them to both backend and LiveKit). |
| One phone never gets call alerts when app is closed | Firebase (FCM) is not configured, or the phone brand blocks background apps. Configure Firebase, and allow the app to run in background in phone settings. Android cannot guarantee alerts after force-stop — this is an Android limit, not a bug. |
| Forgot a user password | Edit `backend/seed/users.json`, change that password, run Step 7 seed again (it updates existing users). |
| Postgres password error after changing `.env` | The database volume keeps the **first** password. Changing `POSTGRES_PASSWORD` later needs the same change inside Postgres, or a fresh volume (data loss — backup first). |

## Security checklist

- [ ] `.env` has fresh random secrets (setup script did this) and is not shared/uploaded anywhere public.
- [ ] `backend/seed/users.json` passwords are strong, different, and the file stays private.
- [ ] Only the ports in Step 3 are open.
- [ ] Backups are copied off the VPS.
- [ ] SSH uses a key, and root password login is disabled (recommended).
